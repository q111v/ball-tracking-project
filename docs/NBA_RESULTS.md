# NBA 篮球调试与验证记录

## 方法及边界

原测试视频保持完整117帧、30 FPS、1280×720，没有换片、降速或写死球坐标。新篮球模式使用公开预训练YOLOv8n，在领域样本上微调后进行多尺度局部搜索；利用人体关键点与一致性光流排除短时漏检的人头，再将有图像检测依据的观察交给 Ultralytics 内置 ByteTrack。离线双向观察只提供候选，时间连续性筛选决定输出；手动指定的目标不能被无关的反向轨迹覆盖。

光流只用于维持“人头排除区域”，不用于虚构篮球坐标。篮球检测缺失时不绘制假球框；历史轨迹也不跨缺失帧画实线。

该模式目前针对单个篮球。多球通用场景仍可使用原来的通用YOLO+ByteTrack模式；不能把单球关联窗口配置直接解释为可靠的多球身份识别。

## 领域微调与可重复性

- 基础权重：公开 `basketball_base.pt`，来源及SHA256见 `models/SOURCES.json`。
- 从目标视频中选取44个训练源帧，包含5个完全遮挡的负样本帧；候选框经原图目视复核。加入局部裁剪和观众负样本后共134张训练图。
- 7个同视频留出帧用于选择权重。它们与训练帧时间相关，因此其分数不能当作独立泛化成绩。
- 15轮微调、seed=7、imgsz=640、batch=4、AdamW、freeze=10；不是从零训练。配置和逐轮结果见 `evidence/domain_training/`。
- 第二段NBA比赛、体育馆训练视频均不参与微调。
- 用 `python -m tools.train_basketball --output runs/retrain` 可重建数据并训练；普通用户运行程序不需要训练。

`training/annotations.json` 保存训练源帧和框；推理模块不读取这些训练标注或测试中心点。

## 原NBA片段结果

实际记录以 `evidence/nba-precision/` 内的CSV、summary、point_evaluation和视频为准。

| 项目 | 原通用YOLO方案 | 新篮球方案 |
|---|---:|---:|
| 视频处理帧数 | 117 | 117 |
| 8个可见中心检查点命中（12像素阈值） | 1/8 | 7/8 |
| 命中点中心平均误差 | 仅少量命中，不作横向均值比较 | 1.13像素 |
| 命中点最大中心误差 | 不作横向均值比较 | 2.55像素 |
| 已知人头/篮筐误跟检查 | 不以漏检替代正确 | 0/9 |
| 有确认ID的观察帧 | 不作为准确率 | 70/117 |
| 新方案观察ID | — | ID=1 |

第106帧篮球与篮网重叠，仍漏检。并不是117帧全都成功检测；这些点检查也不是全片逐帧真值、mAP、IDF1或MOTA。完整人工复核全部输出点的预览保存在 `observation_audit.jpg`。框内中心位置是原图像素坐标，镜头移动也会反映到像素轨迹中。

CPU实测为离线处理，不达到30 FPS实时；新算法与基线的并发负载、线程设置不同，不能把不同运行的FPS当成严格性能对照。`summary.json` 记录请求及实际PyTorch线程数，视频输出仍以源帧率播放。

## 其他篮球视频

区分两个问题：输入文件可处理，与目标定位达到精度要求。新入口支持选择视频、比赛/近景配置和初始框选，但不能对所有未见视频预先保证精准。

自动初始化在另一个NBA片段中仍可能选择观众；失败结果会保留，不能以“有ID”声称成功。新视频默认框选一次球体，以明确目标身份。此框仅初始化，后续观察仍须由模型从图像中产生。

独立验证结果如下，均未参与微调：

| 视频/方式 | 帧数 | 检出框帧数 | 人工可见点命中 | 结论 |
|---|---:|---:|---:|---|
| 第二段NBA，自动初始化 | 174 | 100 | 0/3 | 失败，选错目标 |
| 第二段NBA，手动初始化+身份约束 | 174 | 26 | 1/3 | 仍失败，不能声称通用比赛跟踪通过 |
| 体育馆近景，closeup基础模型 | 90 | 79 | 1/1 | 此短片段可用，单个检查点不足以证明泛化 |

上述计数只是输出覆盖率，不是精确率。第二段比赛虽在手动初始化后避免了反向轨迹覆盖目标，但仍大量漏检；此版本没有达到“后续任意篮球视频精准”的要求。请据此判断是否适合当前实验，不将它作为通用性验收完成版。

原片与近景的实际输出分别在 `evidence/nba-precision/annotated.mp4`、`evidence/practice-validated/annotated.mp4`。失败的第二段比赛也随包提供用于复查。

## 自动化与平台验证

Python 3.11、3.12 各通过25项自动化测试；3.11另外执行了3帧真实模型推理、保存和日志的冒烟测试。完整117帧NBA及其他视频处理在3.12执行。Windows UI、摄像头和GPU未在本次云端实机验证。

## 尚待解决

需要更适合比赛画面的专用权重或更丰富的独立训练数据，而不只是继续调阈值。来源项目公开的约173MB比赛权重未能在当前云环境取得：下载目标域名不在网络允许列表中；这项限制不应被说成模型已验证。
